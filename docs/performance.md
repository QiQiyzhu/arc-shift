## 已完成优化

- v0.2 正常路径复用一张 1600×900 圣所图片纹理并按房间调色，像素约 5.49 MiB（不含驱动/浏览器副本）；加载失败才启用旧四模板程序地面缓存。减少重复几何提交，整个 Phaser Game 销毁时释放。
- 弹体池 420、粒子池 650、飘字池 40；限制并发合成声部为 30。池耗尽会丢弃新增对象，避免无界增长；仍需监测丢弃是否影响玩法。
- React HUD 约每 80 ms 刷新一次，核心模拟和渲染不依赖 React 提交。
- 单帧累计最多 50 ms，避免后台返回无限追帧；代价是严重卡顿会拖慢模拟时间。
- 次生爆炸/连锁/持续伤害关闭完整命中链，避免递归触发爆炸式增长。
- v0.2 分裂代际最多一层、每步反应预算 12、目标反应冷却；音乐声部最多 12、总声部最多 30，共享噪声缓存和延迟节点。
- Scene 与 React 双重清理事件订阅，避免 StrictMode 重建后持有已销毁表现对象。

## v0.1 完整流程规则样本（历史）

[18 局报告](qa/simulation-results.json)：3 个种子 × 3 个初始协议 × 2 类路线。全部到达胜利，峰值 11 个敌人、42 枚弹体，池耗尽为零。包含安全房的战斗模拟耗时 268.53–288.47 秒，全战斗路线 407.02–422 秒，不含选卡决策与介绍时间。

`Engine.update` 单步平均 0.0025–0.0089 ms，P99 0.0113–0.0814 ms。此计时排除渲染、音频、浏览器和 Bot 决策开销，只证明该小规模样本的规则执行成本，不能外推渲染 FPS。Bot 能精确读取敌人、弹体和预警，不代表真人通关率。

## 剩余成本与下一步

v0.2 [18 局完整规则结果](qa/simulation-v02.json)全部胜利，模拟战斗时间 270.3–428.45 秒，峰值 14 个敌人 / 41 枚弹体，池耗尽为零。Engine.update 单步均值 0.0015–0.0051 ms、P99 0.0058–0.0395 ms；同样排除 Bot 决策、渲染和声音，不代表真人胜率或显示帧率。

敌人分离约 O(E²)，普通弹体碰撞约 O(P×E)。v0.2 追踪已改为最近目标线性扫描；连锁仍有 filter/sort 临时分配，池获取仍可能扫描全部槽位。现有规模优先保持规则清晰；增加敌群前应引入空间网格、复用查询数组，测量后再优化。

本版生产 JavaScript 为 1,591.07 kB，gzip 450.04 kB，CSS 172.39 kB，gzip 29.57 kB，主要脚本包含 Phaser。v0.2 增加两张本站 WebP 图片，合计 437,586 字节（约 427 KiB）；字体本地托管，音乐现场合成，无第三方素材服务请求。还未完成慢网络首屏指标、多 GPU 对比、移动设备游戏性能、十分钟以上 heap 曲线或动态画质分级。
