# 性能记录

测量日期：2026-09-08。固定步为 60 Hz 不等于渲染达到 60 FPS。以下数据区分 Node 规则执行、浏览器渲染与操作系统调度，不用规则耗时推算显示帧率。

## 浏览器压力样本

环境：本机 Windows、headless Microsoft Edge 152，视口 1920×1080、内部画布 1280×720、Vite 开发构建。28 个敌人、高生命压力场景；玩家三发弹、穿透、连锁、燃烧、追踪、爆炸，同时使用 Q / E。采样 requestAnimationFrame 间隔约 10 秒，测试源见 `e2e/performance.spec.ts`。这是人工构造压力夹具，不是自然奖励下的 Build 平衡测试。

## 已完成优化

- 静态地面烘焙为纹理，每种装饰模板一次；最多四张 1280×720 RGBA 纹理，原始像素约 14.1 MiB，不含浏览器副本与额外开销。切房复用，整个 Phaser Game 销毁时释放。
- 弹体池 420、粒子池 650、飘字池 40；限制并发合成声部为 30。池耗尽会丢弃新增对象，避免无界增长；仍需监测丢弃是否影响玩法。
- React HUD 约每 80 ms 刷新一次，核心模拟和渲染不依赖 React 提交。
- 单帧累计最多 50 ms，避免后台返回无限追帧；代价是严重卡顿会拖慢模拟时间。
- 次生爆炸/连锁/持续伤害关闭完整命中链，避免递归触发爆炸式增长。
- Scene 与 React 双重清理事件订阅，避免 StrictMode 重建后持有已销毁表现对象。

## 完整流程规则样本

[18 局报告](qa/simulation-results.json)：3 个种子 × 3 个初始协议 × 2 类路线。全部到达胜利，峰值 11 个敌人、42 枚弹体，池耗尽为零。包含安全房的战斗模拟耗时 268.53–288.47 秒，全战斗路线 407.02–422 秒，不含选卡决策与介绍时间。

`Engine.update` 单步平均 0.0025–0.0089 ms，P99 0.0113–0.0814 ms。此计时排除渲染、音频、浏览器和 Bot 决策开销，只证明该小规模样本的规则执行成本，不能外推渲染 FPS。Bot 能精确读取敌人、弹体和预警，不代表真人通关率。

## 剩余成本与下一步

敌人分离约 O(E²)，普通弹体碰撞约 O(P×E)。追踪与连锁有 filter/sort 临时分配；池获取仍可能扫描全部槽位。现有规模优先保持规则清晰；增加敌群前应引入空间网格、复用查询数组，测量后再优化。

首版生产 JavaScript 约 1.57 MB，gzip 约 443 KB，主要包含 Phaser。没有外部图片与音频下载；字体本地托管。还未完成慢网络首屏指标、多 GPU 对比、移动设备游戏性能、十分钟以上 heap 曲线或动态画质分级。应把这些列为后续实测，不能写成已完成优化。
