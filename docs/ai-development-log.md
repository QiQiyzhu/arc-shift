# AI-assisted engineering workflow

## v1.0 钟声尽头（2026-09-10）

用户提出局内混搭、完整路线规划、碎片叙事、Boss 配乐、地形和解锁要求，并要求可发给面试官的在线作品。主执行者实现与集成源码、界面、绘制、测试和发布。只读代理审查玩法、存档和证据，资产代理只在工作树外生成两张原创地面，主执行者检查并转换整合。未由子代理并行改写 Sites 工作树。

实际修复包括慢速协议造成圣剑连段中断、守点无限刷取收益、恢复入口叠加遗器护盾、旧行动未记录 Boss 解锁、主遭遇奖励隐藏额外交易，以及同一营地内换武器后试炼仍引用旧选择。新增规范路线与事件状态校验。浏览器检查使用明确开发场景到达后期，不包装为真人整局；模拟控制器只通过输入和合法路线/事件操作完成行动。

## v0.3 遗珍迭代（2026-09-10）

主执行者完成钱包、拾取、营地交易、局外准备、武装分派、几何特效、音效和 UI，并扩充自动验收与文档。独立只读代理研究参考作品的资源取舍，并分别审查武器、经济与存档。源代码、测试修复和发布均由主执行者实施，代理没有并行修改 Sites 工作树。

审查后修复：圣剑穿透单卡没有产生符刃；圆与扇形角点碰撞过宽；Oracle 无限召唤产生经验、物资和吸血；试炼初始武器没有随主菜单更新；存储不可用时营地仍承诺保存。新增规则回归验证这些边界，浏览器实际输入验证 B / R 与暂停引信，营地按钮和页面刷新验证持久化。全程保留 v0.2 的原创图片与音乐，没有复制竞品资产。

## 分工与责任

本项目由用户提供目标、范围、原创方向和阶段顺序，Codex 主代理负责实现、集成、测试与交付。独立子代理承担竞品/许可证研究、战斗设计建议、只读代码审查和完整流程模拟。Site checkout、部署、版本管理均由主代理操作。

这是 AI 辅助工程项目。代码与文档有大量 AI 生成内容；没有把自动执行描述为人工完成，也不把 AI 自评当作独立玩家评价。作品集提交者应亲自验证手感、理解代码、复现测试，并对最终设计与质量负责。

## 审查推动的修复

1. 高频显示器中技能输入丢失：从逐帧 JustDown 改为事件锁存，并处理同帧按下/释放。
2. Dash 缩短已有无敌：取两段无敌的较大值。
3. 贴墙反弹失效：反射时修正弹体位置。
4. 死亡后同 tick 吸血：加系统间死亡门控。
5. 火迹重叠输出过高：按移动距离生成范围。
6. Boss 背面激光无预警：预警和命中复用同一双向线段。
7. React StrictMode 重建场景后访问销毁纹理：同时处理场景 shutdown/destroy 和组件清理。
8. 三重星火升级与续玩数值不同：统一调用属性推导函数。
9. 护盾恢复丢失、失败 resume 重置结算锁、跃迁冰环误赋予普攻减速：增加相应恢复/状态边界检查。
10. 安全路线过多：限定第 3 与第 6 区域提供安全分支。
11. Boss 介绍时打开设置或失焦，底层继续进入战斗：暂停保存并恢复原阶段，弹窗阻止输入；加入真实浏览器超时验证。
12. 静态地面重复提交几何：烘焙并缓存四种模板；保留优化前后 10 秒压力采样，未将小幅差异夸大为稳定 60 FPS。

## v0.2 共振迭代（2026-09-09）

用户要求重点参考以撒的技能效果搭配，并升级素材、美术、音乐和流派。主代理实现 10 项新协议、攻击的三层组合、六种反应与试炼、音频乐谱和界面集成。独立资产代理只在 checkout 外生成两张原创新图片；主代理检查后压缩成 WebP。生成过程见美术记录，没有导入商业游戏资产。

只读机制和音频审查推动修复了次生反应重复死亡结算、环绕贴墙反弹、分裂寿命门槛、音乐限流与重建边界。最后一轮审查用四向射击复现“回旋弹先撞墙销毁”，主代理加入早返航并补中央与贴墙测试。试炼顶部遮挡和无限波显示也在截图复核时修正。

新增真实浏览器试炼、存档保留、音量总线、失焦与上下文重建检查；以两种 28 敌人压力场景区分旧夹具与本轮多形态叠加，重新运行三起始协议的 18 局规则模拟。测试结果与原始数据随文档保留，不把代码组合数或 Bot 胜利数等同于玩家策略质量。

## 2026-09-10 · Engineering M1–M2

AI 主代理审计已有引擎、输入、战斗、经济、存档和测试，建立 JSON 基线及阶段检查脚本。基线暴露两项问题：奖励可能提升最大生命而旧 E2E 写死数值；暂停期间已挂起的 AudioContext 不能执行音量渐变。分别修正断言依据和暂停总线的即时归零，并增加音频生命周期测试。M1 实际通过 93 unit / 25 browser tests、typecheck、lint、build。

AI 实现 Uniform Grid、连续扫掠候选查询和动态分离遍历，保留原算法作 oracle。新增 5 项参数化属性/整局对照测试，覆盖负坐标、大半径、高速弹体、穿透、击退、分裂、对象池和固定种子状态一致性。首轮性能回退没有隐藏；后续通过缓存 cell 边界减少维护/排序开销。性能原始 JSON、阶段输出和 CPU 汇总随仓库保存。自动验证支持碰撞等价及该夹具的性能结论，不能替代真人游玩或跨设备测量。

## 2026-09-10 · Engineering M3

AI 主代理实现固定步输入观察点、带执行结果的决策记录、可选持久化依赖、ReplayRecorder/Player、严格 JSON 导入与开发回放页。另一个 AI 代理只读审查，实际复现了菜单布景覆盖状态、失焦暂停串入回放、checksum 洪泛、legacy Boss 引用漏检、命令结果未验证、负零 seed 和 30 分钟小数坐标录制超限的问题。主代理逐项修正，并加入可执行回归用例。两次完整验收另暴露 QA 延迟加载的就绪竞态、随机加血奖励使旧契约断言失效；修正等待条件与奖励前状态快照，保留失败报告。最终 `docs/qa/engineering/m3-replay-verified/checks.json` 的 typecheck、lint、115 项单元测试、27 项浏览器测试和 build 全部通过，其中包含 17 项回放单元用例和 2 项真实浏览器回放流程。

## 2026-09-10 · Engineering M4

AI 主代理提取参数 schema，接入 World/Engine、协议推导、攻击几何、生成波次与 Boss 阶段，构建 DEV 内容编辑器和真实训练沙盒。500 组构筑对照固定到提取前提交的实际输出哈希；9 项新单元用例验证默认等价、参数消费者、引用循环、版本和持久化边界。两项浏览器流程实际验证导出再导入、无效草稿阻止应用、生成敌人数值和运行沙盒。首轮浏览器用例错误地假定首张目录卡为 fire-ember，修正为按稳定 ID 选择后通过；完整阶段 `m4-content/checks.json` 的五项检查全部成功，124 单元 / 29 浏览器测试。

格式化曾因 Windows 文件映射锁未能写入部分文件；没有强制终止其他程序或把格式化输出当测试通过。随后实际 typecheck、lint、unit、E2E、build 均通过。为降低 C 盘占用，确认 ARC 无运行进程后，将可重建依赖迁至 `D:/CodexData/ARCShift/node_modules` 并用目录 junction 保留路径；完整阶段检查也验证该本机安排可工作。

## 2026-09-10 · Engineering M5

AI 主代理实现独立训练调试页、固定步调速/单步、实时池/网格/FSM 指标及只读命中框绘制。协议发放与正式奖励共享验证后的 mutation，开发入口通过 DEV 条件隔离。4 项单元测试验证输入锁存、时间倍率与无副作用指标，真实浏览器测试运行到实际战斗后验证 Boss、协议、网格及存档隔离。第一轮完整回归发现奖励卡多项共鸣说明将重抽按钮挤至 HUD 后方；修复为区域内滚动，并增加 900/768 高度真实点击回归。最终五项检查通过，128 单元 / 32 浏览器；失败和成功原始报告均保留。调试器截图是实际浏览器画面，瞬时读数不作为性能提升结论。

## 2026-09-10 · Engineering M6

AI 主代理增加长期模拟、12 个随机种子短局、3 份提交的回放历史、4 项存档兼容回归及生产构建检查。审计发现旧版存档中的未知 Boss 引用会绕过普通存档校验，修复为仅舍弃损坏检查点并保留有效进度；因此一项旧回放错误信息断言失败，按新的更早校验边界修正后完整回归通过。另一 AI 代理只读审查存档/脚本并实现 CI；审查推动补上 soak 最后 tick 的完整不变量和 bundle 的非空入口检查。6 种子各 108,000 tick 的真实 Node 模拟完成，零池 miss，原始 heap 与耗时保留，但不声明浏览器三小时无泄漏。最终 136 单元 / 32 开发浏览器及五项 gate 全部通过，另行 1 项生产构建浏览器检查成功。CI 定义已验证语法，只有远端实际成功后才声明 Linux 验收完成。

## 2026-09-10 · Engineering M7

AI 主代理将浏览器设备输入抽象为 ActionInput，接入键位冲突校验、独立配置存储、标准手柄快照、死区、技能边沿和当前操作提示。独立只读审查发现两类真实边界：隐藏窗口停止轮询后，恢复的首个快照可能把已按住 Start 当作新按下；手柄断连重连也会重复产生 Pause/Bomb。修复为仅对手柄建立按钮基线，保留恢复焦点后新到的键盘动作，释放重按后才重新生成技能边沿。专门的 Node 回归覆盖这些序列；浏览器同时覆盖持续失焦和同一 JS task 内没有中间帧的切回。

首轮 M7 完整 gate 为 144 单元 / 34 浏览器通过。后续完整回归出现两项失败：键鼠接管检查向下移动时实际撞墙；奖励布局夹具早于 Phaser 场景初始化，被正常菜单布景覆盖。实际截图证明问题所在，改为沿已走过的路径返回以及等待启动按钮真正就绪，未削弱地形碰撞或强制点击按钮。首次 Linux CI 的五个 smoke 失败另行保留；修复额外 Phaser delta smoothing 与不完整焦点事件后，仍需看新的远端实际结果，不能以本地成功替代。

依赖审计报告原有 6 个受影响包条目（4 high、2 moderate），根因属于 mocker 和 sharp 开发工具链。定向更新 Vitest 4.1.11、override sharp 0.35.4 并更新 lockfile，实际重新审计为 0；没有接受工具建议的广泛降级。CI 增加中危及以上 audit gate 与输入 smoke。最新完整阶段及生产检查以 `qa/engineering/m7-input-verified/` 的实际记录为准。实体 USB/Bluetooth 手柄未测，API fixture 不是硬件兼容性结果。

## 玩家判断仍不可替代（持续）

自动 Bot 精确读取世界和弹体状态，不代表真人胜率；运行几秒的帧采样不代表所有硬件稳定 60 FPS；截图一致不代表长期游玩不疲劳。玩家读招成本、局长、Boss 记忆点、音效疲劳和组合乐趣仍需要真实玩家测试。
