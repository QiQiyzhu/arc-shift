# 项目面试指南

本指南基于已实现代码。提交者应亲自运行、修改一条规则并复现测试，用自己的语言解释；不要把 AI 生成或自动模拟改写为个人手写或真人测试经历。

## 30 秒介绍

ARC//SHIFT 是一个原创网页动作 Roguelite。我用它展示移动射击、Dash、五系构筑、两种 Boss 和完整八区域循环。v0.2 增加形态、轨迹、载荷组合与六种跨系反应。TypeScript 规则与 Phaser 表现分离，React 负责界面。重点工程问题是高速弹体碰撞、反应递归边界、场景生命周期和检查点恢复。项目由 AI 辅助实现，有自动测试和浏览器验收，并记录性能证据的实际边界。

## 2 分钟介绍

先在协议试炼演示冰环、回旋与 Dash，再展示奖励的组合补齐提示。解释形态、轨迹、载荷可同时作用，以及次生弹不递归触发完整命中链。退出试炼继续原检查点，展示战斗 → 奖励 → 路线 → Boss 循环。

打开 Engine，说明固定步顺序是玩家、AI、弹体、危险区。伤害系统只改规则数据，通过 EventBus 通知音效、粒子和镜头；特效不决定命中。高速弹体使用扫掠线段，激光的预警和命中共享几何。

讲一次实际修复：StrictMode 重建 Phaser 场景后，旧订阅仍调用已销毁纹理，首次受击报错。修复同时覆盖 Scene shutdown/destroy 与 React cleanup，浏览器测试检查表现订阅者数量。最后说明 50 项规则测试、9 组浏览器验收与 18 局模拟的不同证据边界。

## 22 个常见问题

### 1. 为什么选择 Phaser？

它提供浏览器场景、输入、Canvas/WebGL、缩放和 Graphics，适合图片地面与代码角色/VFX 混合的 2D 项目。规则层没有引用 Phaser，选择框架不锁定伤害与构筑模型。本项目没有使用 Arcade Physics，不应把自写圆形碰撞说成物理引擎能力。

### 2. TypeScript 带来什么？

敌型、阶段、卡牌和输入用明确类型约束，属性推导与事件数据有编译期检查。它不能证明数值平衡或存档可信，所以仍有运行时解析和测试。

### 3. 主循环如何工作？

每渲染帧采集输入并累计时间，按 1/60 秒执行规则，再绘制世界。单帧最多计入 50 ms；连续输入保持状态，Space/Q/E 用事件锁存后只消费一次。严重低帧率会减慢模拟，没有承诺锁步同步。

### 4. 敌人 AI 如何实现？

共享实体数据、按敌型选择行为。猎手追击，哨兵远程射击，冲锋者锁定方向后突进，织网者制造危险区，导体增加协同压力。移动含简单敌人分离，无障碍寻路。

### 5. 状态机的价值是什么？

预警、攻击、冷却/恢复分别控制移动、计时和伤害窗口，避免每帧重新随机决定动作。Boss 再叠加血量阶段。当前使用类型与分支实现，没有独立图形化状态机编辑器。

### 6. 如何避免高速弹体穿过目标？

使用弹体前一位置到新位置的线段与目标圆做扫掠检测。穿透弹记录命中 ID，避免停留在圆内每 tick 重复伤害。反弹修正位置后改变速度，防止持续越界反射。

### 7. 弹幕多时怎样优化？

先限制生命周期和总量，复用弹体对象，再测碰撞开销。目前 O(P×E) 在规模增大后是风险；下一步是空间网格筛选候选，不能只靠对象池解决查询成本。

### 8. 为什么使用对象池？

高频创建销毁容易增加分配与垃圾回收抖动。弹体、粒子、飘字复用槽位且有明确上限。池耗尽计数需要监测；零耗尽只对当前样本有效。

### 9. Buff 如何管理？

燃烧、减速等短状态直接存实体字段；Build 的长期属性由卡牌与等级推导。这样简单但扩展大量叠层、驱散、优先级时会变难，应再抽象实例化 Buff 容器。当前不是通用 Buff 引擎。

### 10. 怎样扩展一个技能？

数值型协议加入目录、前置关系和属性推导；特殊行为增加系统处理与相关事件。新技能需说明目标、时机、冷却、次生触发规则，并测试关键边界。

### 11. 随机性怎么控制？

使用种子 RNG；房间与奖励有派生种子，战斗随机消费不改变卡牌候选。存档记录种子与已选路径；这还不是逐输入可回放或跨平台完全确定性。

### 12. 怎么避免无用 Build？

候选排除重复和缺前置卡，偏向已有分支，同系三张提供共鸣。测试检查资格和可达组合；真人策略空间与强弱差距仍需试玩，18 局 Bot 通关不能证明五系平衡。

### 13. UI 为什么和战斗分开？

React 管理菜单与可访问的按钮/弹窗，规则状态由 Engine 管理，HUD 约 12.5 Hz 读取。规则无需 React 就能执行测试。代价是 UI 有最多约 80 ms 视觉延迟，并需明确处理弹窗对输入和时间的阻塞。

### 14. EventBus 的取舍？

伤害不直接依赖粒子或音频，增加表现订阅者方便。代价是流程不直观、订阅生命周期容易泄漏。此项目用显式 unsubscribe 和 StrictMode 场景重建测试守住边界。

### 15. 动画与逻辑怎么同步？

角色状态和计时来自规则；Renderer 读取状态绘制预警，表现事件产生一次性反馈。Oracle 激光两侧的预警和命中使用同一几何函数，避免画面安全但逻辑判定受伤。

### 16. Boss 如何设计？

第 4 区域偏向扇形射击、突进和范围压迫；第 8 区域使用环形弹幕、旋转双向激光和召唤。血量跨 65%/30% 改变阶段，切阶段清理旧敌弹与危险区，给玩家读招机会。

### 17. 怎么达到 60 FPS？

先回答实测：v0.2 本机 headless Edge 两种短样本平均约 67.9 / 79.5 FPS，P95 仍超过 16.7 ms，不能声称稳定 60 FPS。已有池化、单图地面复用、低频 HUD 和次生反应预算；下一步前台生产采样，定位 Graphics、布局、碰撞与调度，再按瓶颈优化，不能从固定 60 Hz 模拟推导渲染 60 FPS。

### 18. 测试覆盖什么？

Vitest 验证碰撞、伤害、卡牌、随机、存档与暂停；Playwright 用真实键鼠验证操作和界面，并用 DEV 夹具进入 Boss/结算等场景。独立 Bot 通过合法输入跑完整规则流程。三种测试互补，均不替代真人手感评估。

### 19. 玩家数或规模增长的瓶颈？

当前是单机单玩家。更多敌人先增加 O(E²) 分离与 O(P×E) 碰撞成本；多人需要全新的权威状态、协议、预测与校正设计，不能说现有事件总线就能扩为多人。

### 20. 移植 Unity 怎么做？

保留数据和系统边界，将 World/规则翻译为 C#，场景与渲染改用 Unity 对象或实例化绘制，UI、音频、输入与存储替换适配层。复用规则用例做行为对照，不假称能直接复制 TS 运行。

### 21. AI 具体做了什么？

AI 生成大量代码和文档，完成集成、测试执行、网页验证与发布；独立代理做只读审查和模拟。用户提出目标与方向。可用开发日志展示真实贡献，不把自动产生的实现包装成人手编写经历。

### 22. 开发者必须做哪些判断？

确定范围与原创边界，检查生成代码，理解设计取舍，亲自验证操作反馈，判断性能证据与玩家反馈，承担发布责任。面试最可信的展示是现场解释并修改一条规则，运行测试说明改变了什么。
