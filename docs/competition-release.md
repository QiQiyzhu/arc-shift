# ARC//SHIFT 1.1 · 共鸣与演练

本轮目标是让第一次接触作品的人更快玩到它的核心组合，同时继续处理此前「模拟更快、浏览器未明显更流畅」的问题。2026-09-10 实施；原十二层路线、三种主武装、协议与遗器、经济、Boss、正式存档及确定性回放规则保留。

## 玩家现在能直接体验什么

- 主菜单「第一次跃迁 / 行动演练」：移动、命中固定靶、跃迁、脉冲、二选一熔接、实战共鸣、守门人。基础提示支持跳过；演练无敌，不写正式行动与营地进度。完成时显示来自模拟的净化与爆发反应数（只计电浆、热裂变、坍缩；折光等共鸣不计入）。时间取决于实际操作，未声称真人均能三分钟完成。
- 选卡显示同一 `deriveStats` 算出的前后变化、收益与代价、跨系反应条件、还缺的具体协议、同系三张加成。对圣剑/重炮明确区分协议基础数值和武器倍率，不把简单属性乘积当实际 DPS。
- 六格角色图集完成接入、池化与缺失回退；受击不再长时间变成大片白色剪影，玩家中心标记保持稳定，敌弹使用不透明外沿与明亮内核，并位于友方装饰层上方。
- 新增战斗清晰模式；减少动态效果同时抑制角色摆动、残影、环境漂浮光点和部分装饰粒子，攻击预警继续可见。
- 结算提供本局累计承伤、爆发反应数和规则提示。这是本地规则提示，不是模型生成的战绩、诊断或死亡原因归因。

## 工程改动与取舍

1. `ArcScene` 把静态障碍与场地边框绘入一张可替换纹理，动态陷阱与祝祷进度继续绘制。缓存根据 World/terrain 身份及房间变化更新，同种子重开也会清掉上一局特效，纹理数量有界。
2. 角色图像重用 seen-ID 集合和图片池；稳定属性只在创建/复用时设置，深度按 8 像素区间变化时更新。敌弹从逐帧 Graphics 路径改为池化图像。保留旧几何表现用于图集加载失败。
3. React HUD 按显示值签名更新；暂停和主菜单不再以 80ms 间隔重复刷新相同内容。技能小数显示与可用状态分开比较，炸弹冷却同样触发刷新。
4. 新手演练是可丢弃的 practice 导演，没有把异步模型接入固定步战斗循环，也未改变正式规则或重写旧回放夹具。显示设置保留可选字段兼容性。
5. 浏览器检查发现 StrictMode 清理后仍可能执行异步 QA 注册，导致诊断接口绑定旧 Scene。注册和加载完成回调现在都检查 effect 生命周期与 Scene 身份，防止过期回调覆盖当前实例。此接口只在 DEV 存在。

## 同机性能证据

原始数据见 [最终复测对照](qa/competition-v3/comparison-after-verified.json) 及同目录 before/after-verified JSON；首次 after 与 comparison 也保留。Windows、Headless Edge、1440×900、Intel UHD / ANGLE D3D11；每场 1.2 秒热身后采样 5 秒，28/100/250 敌分别三次；完整特效，相同输入和高生命敌人。记录附源码 SHA-256、浏览器和 Node 版本、rAF P50/P95/P99、慢帧比例、模拟 tick、池缺失。下表空地形 after 使用生命周期修复后的复测；含地形仍使用已核验有效的原三轮样本。

| 场景 | 优化前 P95 中位数 | 优化后 P95 中位数 | 三次优化前 → 后模拟 tick |
|---|---:|---:|---|
| 28 敌，空地形压力夹具 | 27.8 ms | 27.7 ms | 303/302/302 → 302/302/303 |
| 100 敌，空地形压力夹具 | 34.7 ms | 27.8 ms | 304/301/302 → 302/304/302 |
| 250 敌，空地形压力夹具 | 62.5 ms | 34.7 ms | 291/292/292 → 303/303/303 |
| 100 敌，含正式路线障碍与动态陷阱 | 34.7 ms | 34.7 ms | 302/301/303 → 302/302/302 |

250 敌样本的 P95 中位数降低约 **44.5%**，模拟推进反而更多，不能用「少算 tick」解释收益。28 敌差异只有约 0.1ms，不认为是显著改善；含地形样本未观察到 P95 中位数改善，不能将整轮收益单独归功于地形缓存。

限制：顺序前后测量，未随机交错，只有一台设备和三次短样本；含地形 after 首次采样与单元测试在时间上重叠。rAF 包含浏览器调度/合成，不等同 GPU 时间；呈现准备计时也不含全部 GPU 工作。50ms delta 上限仍保留，报告同时给出模拟推进。上述结果不是全设备 60FPS、统计显著性或真人体验结论。

初次 after 中 (repeat, enemies) 为 (0,28)、(1,100)、(2,100) 的嵌套 `scene` 整组指标受上述过期 QA 引用影响，值为零，**不能用于池数量、地形缓存或呈现计时判断**。独立采集的顶层 rAF、Engine.update 和模拟 tick 不受影响。保留原始坏样本与初始测量脚本，不回填伪造计数。最终九轮复测通过 QA 身份稳定和 Scene 帧数持续增加断言，源码哈希扩大到敌弹、粒子、HUD、QA 和测量脚本。250 敌慢帧占比（>33.3ms）中位数 42.31% → 10.90%；这不是平均 FPS 的等价换算。

## DeepSeek 的实际参与

用户授权后通过进程标准输入提供凭据，项目、浏览器、报告中均不含密钥。一次官方 API 请求，请求模型 `deepseek-chat`，响应模型 `deepseek-flash`；10,423 输入 + 1,500 输出 token，8,063ms，HTTP 200。输出因 token 上限截断，保留这一事实；没有为凑完整意见盲目重试。账单费用未知。[脱敏请求内容与响应](qa/competition-v3/deepseek-review.json)。

| 建议 | 本地核对与处理 |
|---|---|
| 跃迁冷却残留可能令教学跳步 | 进入跃迁步骤时重置冷却，要求该步骤内执行；原代码每帧读满冷却，所谓低冷却漏采样并未复现。 |
| Q 冷却可被无关系统改写 | 当前演练不含该条件，且进入步骤已清零；不把推测当发现。 |
| choose 恢复 playing 是错误 | 这正是选择后开始实战的预期，未接受该解释。但另一个本地只读审查发现 Esc 导致双切换，已禁止 forge 暂停输入并改为条件恢复。 |
| 三张以上缺基础效果时不显示提示 | 扩展到至少三张的候选预览，继续说明基础效果前提。 |
| 缺失协议集合可能误报 | 现有去重内容和过滤条件不支持该断言，未据此改写正确逻辑。 |

这是一份设计/代码复核回执，不是 AI 玩法能力基准。AI参与核心玩法的比赛另有资格要求，本版本不宣称符合其 AI 专题赛道。

## 验证与边界

新测试覆盖演练动作推进、模式替换、暂停、共鸣选择、Boss结束、存档保持、选卡增益/代价、旧显示设置兼容、透明抠像与 HUD 冷却可用状态。浏览器覆盖真实移动/瞄准/攻击/跃迁/Q、弹层 Esc、重开池数量、图集网络失败、笔记本选卡布局。Boss结束使用显式 QA 击杀夹具验证流程，不能称作真人自然通关。

最终结果：TypeScript 与 lint 均通过，**157/157 单元测试、37/37 开发浏览器测试、5/5 生产浏览器测试通过**，生产构建成功。新增生产用例用真实按键走完基础演练并选择折光熔接，确认退出后 localStorage 未变化且不存在 `arcQA`。命令与源码绑定见 [验收索引](qa/competition-v3/README.md)；初次失败及修复前记录保留，旧版本数字不作为本轮证据。实体手柄、完整英文界面、真人首次试玩与多设备长时间稳定性尚未验证。

## 面试讲法与亲手复现

「空间索引优化后，Engine 变快但浏览器没有跟着明显改善。我继续测了真实渲染，发现静态 Graphics 仍反复构造路径、角色重复触发深度排序、敌弹产生大量绘图命令；本轮将它们缓存或池化，并减少 HUD 的无效更新。在这台设备的 250 敌短压力场景，P95 中位数从62.5ms降到34.7ms，同时模拟tick没有下降。但常规和地形场景的改善不一致，所以我保留了原始数据，不宣称所有场景稳定60帧。」

可追问：为什么缓存 Graphics 命令不等于缓存纹理？为什么必须同时看 tick 与墙钟？精灵池在重开后如何复用？为什么 `.toFixed(1)` 相同仍需刷新按钮？如何判断模型审查意见是误报？

亲手练习：在本地给 `hudSignature` 暂时移除 `bombCd > 0`，用空场景投炸弹并观察按钮；恢复后运行对应测试。再阅读敌弹纹理与几何回退路径，解释逻辑碰撞半径为什么不受画面缩放控制。用户需亲自理解和复现；本轮实现、研究、测试与文档大量由 Codex 辅助完成。
