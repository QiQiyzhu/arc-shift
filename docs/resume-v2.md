# ARC-SHIFT v2.0 简历与讲解文本

## 项目经历候选

**ARC-SHIFT｜系统、数值与战斗设计 Demo（AI辅助实现）**

- 问题：单纯叠加效果难以体现构筑取舍，额外奖励也可能没有实际用途。实现：设计「武装锁定—预算配置—合约分歧—战斗重配」三阶段循环；结合四槽、前置协议、生命支付和永久维修成本，通过封闭配置复用同一战斗引擎。
- 验证：枚举发现旧末关12点预算已经覆盖全部191种合法组合，额外2点无效；调整为基础9点／夺能成功11点后，可行组合172→191。保留18局固定步、跨武器／合约／种子的成功和失败记录，不以组合数增加宣称平衡完成。
- 表现与工程：完善武器参数预览、Boss动作预警和透明角色表现；校验显示几何与真实伤害位置、旧配置迁移、重复结算及主线兼容；提供公开试玩、实机视频、设计说明与原始证据附件。

适合简历用两条，面试展开第三条。若投战斗策划，可先讲「冲锋接触区比旧预警宽，如何根据真实轨迹补齐胶囊区域」，再讲武器承诺和敌阵组合。只有亲自理解并能解释的内容才保留为个人能力主张。

## 约两分钟讲解

1. 选择法器／剑／炮，说明同样的协议为何改变不同的操作条件。
2. 用6点构筑完成聚群；说明单枚伤害、间隔与实际DPS的区别。
3. 对照补给25与支付20生命+精英挑战；奖励只有清场后入账。
4. 展示9→11的组合枚举和维修−2：为什么新奖励真的改变可行空间。
5. 在开发编辑器修改夺能奖励2→1或协议价格3→2并试玩；说明程序验证的是合法与一致，真人测试才回答是否有趣。
